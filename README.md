# 머니로그

**https://finance-manager-hahhneul.vercel.app**

한국 대학생·사회초년생을 위한 직접 입력형 가계부 + 자산 추적 웹앱.
은행 연동 없이 손으로 기록하고, 보유 주식은 수량·가격으로 평가액을 계산해 순자산에 포함한다.
데이터는 전부 브라우저 안(IndexedDB)에만 있고 서버로 나가지 않는다.

## 보통의 가계부 앱과 다른 점

**정산(N빵)이 별도 기능이다.**
회식비 12만원을 카드로 긁고 4명이 나눠 내면, 보통 앱은 "지출 12만원"으로 남는다.
이 앱은 결제 계좌에서 12만원을 빼고, 정산 받을 계좌에 9만원을 넣고,
**지출 통계에는 내 몫 3만원만** 잡는다. 나누어떨어지지 않는 잔돈은 결제자가 부담해
`내 부담 + 돌려받을 돈 = 총액` 이 항상 정확히 맞는다.

**가계부와 자산 추적이 한 앱에 있다.**
보통 지출 기록과 투자 관리는 앱이 따로다.
여기서는 순자산 = 계좌 잔액 − 부채 + 주식 평가액(원화 환산) 을 한 화면에서 본다.

**서버가 없다.**
은행·카드 연동을 하지 않으므로 계정을 만들 일도, 내 소비 내역이 어딘가로 넘어갈 일도 없다.
대신 직접 입력해야 한다. 그 대가로 **JSON 파일 하나로 전부 들고 나갈 수 있고**,
서비스가 없어져도 내 기록은 남는다.

**숫자를 검증할 수 있다.**
평균 매입가·실현손익·정산 잔돈 같은 계산을 손으로 미리 풀어 두고 테스트로 묶었다(383개).
앱 안 '전체 → 계산 정확성 확인'에서 그 대조표를 직접 볼 수 있다.

**가격이 언제 기준인지 항상 적는다.**
주가 옆에 "기준 9월 22일 오후 03:30"이 붙고, 하루가 지나면 경고 표시가 뜬다.
시세를 못 가져와도 마지막 값을 그대로 쓰고 실패한 이유를 알려준다.

**반복 거래를 마음대로 기록하지 않는다.**
해지한 구독료가 조용히 쌓이면 지출 통계가 틀어진다.
기록할 때가 되면 홈에 안내를 띄우고 확인을 받는다.

**오프라인에서 전부 된다.**
지하철에서도 앱이 열리고 거래를 입력할 수 있다. 네트워크가 필요한 곳은 시세 조회뿐이다.

## 값 표현 규칙

이 규칙이 깨지면 금액이 1원씩 어긋나기 시작한다.

| 종류 | 규칙 |
|---|---|
| 원화 | `number` **정수**. 중간 계산에서 반올림하지 않는다 |
| 달러가·환율·수량 | `number` 소수 그대로 |
| 원화 환산 | `core/money.ts` 의 `toKrw()` 로 **마지막에 한 번만** 반올림 |
| 거래 날짜 | `'YYYY-MM-DD'` 문자열. `Date` 객체를 저장하지 않는다 |
| "오늘" | `core/date.ts` 의 `todayISO()` — 기기 타임존과 무관하게 서울 기준 |

## 설계 원칙

**계산은 UI와 분리한다.** `core/` 는 순수 함수만 두고 단위 테스트를 붙인다.
화면을 갈아엎어도 계산은 그대로 남는다.

**Trade 가 단일 진실 원천이다.** `Holding` 의 수량·평균단가는 매매 기록으로부터
`recomputeHolding()` 이 계산한 결과를 저장해 둔 캐시다. 과거 매매를 수정해도
평균단가가 어긋나지 않는다.

**부호 규칙은 모든 계좌가 같다.** 신용카드라고 계산식을 뒤집지 않는다.
카드로 쓰면 잔액이 음수가 되고 순자산에서 자연스럽게 빠진다.
`isLiability` 는 화면에 "갚을 돈"으로 표시할 때만 쓴다.

**이체와 정산은 통계에서 제외한다.** 이체는 내 돈이 계좌 사이를 옮긴 것이고,
정산금 입금은 수입이 아니다. 이 규칙은 `core/transactions.ts` 의
`statsEntries()` **한 곳에만** 있고 월 합계·카테고리·예산이 모두 그것을 쓴다.

## PWA 배포 대비 (8단계 전까지 지키는 것)

- 코드에 `/` 로 시작하는 절대 경로를 쓰지 않는다. `assetUrl()` 을 쓴다
- 배포 경로는 `src/app.meta.ts` 의 `basePath` 하나만 바꾸면 된다
- 외부 네트워크 없이 앱이 완전히 동작한다. 글꼴도 번들에 들어 있다
- DB 스키마 변경은 `db/schema.ts` 의 `MIGRATIONS` 에 **새 항목만 추가**한다
- 백업 JSON 에 `schemaVersion` 이 들어 있어 옛 백업도 복원할 수 있다

## 차트 색을 정하는 방법

`src/core/chartColors.ts` 의 값은 눈으로 고른 게 아니라 검증기를 통과한 것이다.
색맹 판별 가능성, 밝기 대역, 채도 하한, 배경 대비를 모두 본다.
**슬롯 순서 자체가 색맹 안전성을 만들기 때문에 순서를 바꾸면 안 된다.**

두 가지 규칙만 기억하면 된다.

- **색은 카테고리 자체에 묶는다.** 금액 순위로 칠하면 달이 바뀔 때마다 색이 뒤집혀서
  지난달 차트와 비교할 수 없게 된다.
- **색만으로 값을 읽게 하지 않는다.** 도넛 옆에는 금액 목록이, 달력 칸에는 숫자가
  같이 있어야 한다. 대비가 낮은 색이나 색맹인 경우에도 읽을 수 있어야 한다.
- **상태 색(주의·초과)은 아이콘과 글자를 반드시 같이 쓴다.** 밝은 배경에서 노란색은
  대비가 낮아 색만으로는 읽히지 않는다.

## 반복 거래를 자동으로 기록하지 않는 이유

넷플릭스를 해지했는데 앱이 매달 13,500원을 조용히 적어 넣으면
지출 통계가 틀어지고 나중에 찾아 지우기도 번거롭다.
그래서 기록할 때가 되면 홈 화면에 배너를 띄우고 **확인을 받은 뒤** 기록한다.
건너뛴 것도 `lastGeneratedDate` 를 올려서 매번 다시 묻지 않는다.

## DB 스키마를 바꾼 예 (v1 → v2)

CSV 가져오기 기능을 없애면서 `Transaction.importHash` 를 걷어냈다.
이미 배포된 앱이 있다면 사용자 기기에는 v1 DB 가 들어 있으므로,
**v1 정의는 그대로 두고 v2 를 덧붙였다** (`src/db/schema.ts` 의 `MIGRATIONS`).

- Dexie 가 v1 → v2 로 올라가며 인덱스를 바꾸고, `upgrade()` 가 남은 값을 지운다
- 옛 백업 파일도 `BACKUP_UPGRADES[1]` 을 거쳐 현재 모양으로 올라온다

앞으로 스키마를 바꿀 때 이 두 곳을 같이 손대면 된다.

## 파일 내려받기

`<a download>` 는 대부분 잘 되지만 **아이폰 홈 화면 PWA 안에서는 동작하지 않는다.**
그 경우에만 공유 시트로 넘긴다 (`src/lib/download.ts`).

공유 시트를 기본으로 쓰지 않는 이유: 데스크톱 크롬도 `canShare({files})` 가 true 를 주지만
실제 `share()` 호출이 응답하지 않고 멈추는 경우가 있다.

## 순자산 추이는 어떻게 그려지나

앱을 연 날마다 그날의 순자산을 `NetWorthSnapshot` 으로 한 줄 기록한다
(`ensureTodaySnapshot`, 같은 날 다시 열면 덮어쓴다).
차트는 **각 달의 마지막 스냅샷**만 골라 그린다 — 매일 쌓이면 1년에 365개가 되기 때문이다.

데모 데이터에는 과거 6개월을 거래 기록에서 **역산**해 채워 뒀다(`netWorthAsOf`).
현금·부채는 정확하지만 그날의 주가를 모르므로 주식은 **취득원가**로 평가한다.
그래서 과거 구간은 실제보다 완만하다. 실제 사용자 데이터에는 역산하지 않는다.

## StrictMode 와 경합

React StrictMode 는 effect 를 두 번 실행한다. 그대로 두면
"저장소가 비었나?"를 두 번 확인하고 둘 다 "비었다"고 판단해 데이터를 두 벌 넣는다.
스냅샷처럼 유니크 인덱스가 있는 테이블에서는 `ConstraintError` 로 앱이 통째로 멈춘다.

- `seedIfEmpty()` 는 진행 중인 작업을 공유한다 (모듈 수준 promise)
- 스냅샷 upsert 는 읽기·쓰기를 한 트랜잭션에 묶는다

## 시세 가져오기

### 고른 것과 그 이유 (2026-09-22, 실제 호출로 검증)

| API | CORS | 무료 한도 | 한국 주식 |
|---|---|---|---|
| **KRX Open API** ← 채택 | 허용 | 10,000회/일 | 전 종목 |
| Alpha Vantage | 허용 | 25회/일 | 불확실 |
| Twelve Data | 허용 | 800회/일 | 유료 $29/월~ |
| Finnhub | 허용 | 60회/분 | 유료 |
| **open.er-api.com** ← 환율 채택 | 허용 | 키 불필요 | — |

해외 무료 API 는 대부분 미국 주식만 준다. 한국 주식은 KRX 공식 API 가 유일하게 무료였다.

### KRX 호출 방식

**인증키를 쿼리 파라미터로 보낸다.** 그래야 단순 요청이 되어 preflight 가 없다.
커스텀 헤더(`AUTH_KEY`)로 보내면 preflight 응답에 `Access-Control-Allow-Headers` 가
없어서 브라우저가 막는다.

```
GET https://data-dbg.krx.co.kr/svc/apis/sto/stk_bydd_trd?basDd=20260921&AUTH_KEY=...

{"OutBlock_1":[{"BAS_DD":"20260921","ISU_CD":"005930","ISU_NM":"삼성전자",
                "MKT_NM":"KOSPI","TDD_CLSPRC":"274000", ...}, ...]}
```

- 한 번 호출로 **전 종목**(KOSPI 942개, 약 290KB, 3초) → 종목이 몇 개든 시장당 1회
- **일별 종가**다. 실시간이 아니다 (앱 스펙이 원래 실시간을 하지 않는다)
- 기준 시각은 그날 장 마감(15:30 KST)으로 잡아 화면에 "기준 9월 21일 오후 03:30" 으로 띄운다

### 휴장일 처리

주말·공휴일, 그리고 **장 마감 전의 오늘**은 빈 배열이 온다.
그래서 오늘부터 최대 10일을 거슬러 올라가며 데이터가 있는 날을 찾는다.
한 번 찾으면 그 날짜를 두 시장에 똑같이 쓴다 (기준일이 어긋나면 안 된다).

### 실패해도 앱은 멈추지 않는다

못 가져온 종목은 저장된 값을 그대로 두고, **어느 종목이 왜 실패했는지** 적는다.

```
2개 종목 갱신 · 1개 실패 · 환율 갱신
AAPL · 한국거래소에서 가져올 수 없는 시장입니다. 가격을 눌러 직접 입력해 주세요.
       저장된 $200.00 을(를) 그대로 씁니다.
```

미국 주식은 KRX 로 못 가져온다. 직접 입력으로 두거나 나중에 다른 API 를 덧붙이면 된다.
시세는 자동으로 반복 호출하지 않는다 — 새로고침 버튼을 누를 때만.

### 인증키

설정 화면에서 받아 IndexedDB 에만 둔다. 코드에 하드코딩하지 않고,
백업 JSON 에도 담기지 않는다 (파일이 남의 손에 들어갈 수 있다).
기기를 바꾸면 다시 입력해야 한다.

## PWA

### 서비스워커

`vite-plugin-pwa` 로 생성한다 (`vite.config.ts`). 눈여겨볼 설정 네 가지.

```
globPatterns: ['**/*.{js,css,html,svg,png,woff2}']
```
지연 로딩한 화면(예산·투자·설정 등)까지 전부 미리 받아 둔다.
빠지면 오프라인에서 아직 안 열어본 탭이 열리지 않는다.

```
maximumFileSizeToCacheInBytes: 3MB
```
기본 한도가 2MB 인데 Pretendard 가변 폰트가 2,057,688 바이트다.
그냥 두면 **조용히 빠져서** 오프라인에서 글꼴이 깨진다.

```
registerType: 'prompt' · skipWaiting: false
```
거래를 입력하는 중에 페이지가 새로고침되면 치던 내용이 날아간다.
안내만 띄우고 사용자가 누를 때 넘어간다.

```
clientsClaim: true
```
없으면 `skipWaiting()` 이 실행돼도 옛 워커가 페이지를 계속 쥐고 있다.
배너는 뜨는데 눌러도 그대로인 증상이 난다 (실제로 겪었다).

### 업데이트 적용 순서

`src/pwa/UpdateBanner.tsx` 에서 직접 처리한다. 순서가 중요하다.

1. `updateServiceWorker(false)` — 넘겨받기만 시킨다. 새로고침은 맡기지 않는다
   (`true` 로 맡겼더니 새로고침이 아예 안 일어나는 경우가 있었다)
2. **`controllerchange` 를 기다린다** — 새 워커가 페이지를 넘겨받을 때까지
   (안 기다리고 바로 새로고침하면 옛 워커가 옛 화면을 그대로 내준다)
3. `window.location.reload()`

이벤트가 안 오면 3초 뒤 그냥 진행한다. 새로고침만 해도 결국 새 워커를 만난다.

### 저장소 영구 보존

`navigator.storage.persist()` 를 앱 시작 시 한 번 요청한다 (`src/pwa/persistStorage.ts`).
결과는 '전체' 탭의 저장소 카드에서 볼 수 있고, 거절됐으면 다시 요청할 수 있다.

이 앱은 서버가 없어서 기록이 브라우저 안에만 있다.
**아이폰 사파리는 7일 동안 안 쓰면 저장된 데이터를 지운다.**
홈 화면에 추가한 앱은 이 규칙에서 빠지므로, 설치 안내를 카드에 같이 띄운다.

### 사전 점검에서 고친 것

- **빈 상태로 시작할 출구를 만들었다** ('전체 → 데이터 비우기').
  `seedIfEmpty()` 가 `demoSeeded` 를 보게 고쳐서, 비운 뒤 데모가 돌아오지 않는다
- **지연 로딩 실패에 `RouteError` 를 붙였다.**
  오프라인 / 새 버전 배포 후 옛 페이지, 두 경우를 갈라 안내한다

## 배포 (Vercel)

```bash
# GitHub 저장소를 만들고 올린다
git remote add origin https://github.com/<사용자명>/finance-manager.git
git push -u origin main
```

**vercel.com** → GitHub 로그인 → **Add New Project** → 저장소 선택 → **Deploy**.

> **Settings → Deployment Protection → Vercel Authentication 을 꺼야 한다.**
> 켜져 있으면 Vercel 에 로그인한 브라우저만 접속되는데, 폰은 로그인돼 있지 않아
> 홈 화면에 추가해도 매번 로그인 화면이 뜨고 서비스워커도 등록되지 않는다.
> 이 앱은 기록이 각자 브라우저에만 있어서, 주소를 알아도 남의 가계부는 보이지 않는다.
Vite 를 자동 감지한다 (빌드 `npm run build`, 출력 `dist`).
이후로는 `git push` 만 하면 자동 배포된다.

`vercel.json` 이 캐시 헤더를 정해 둔다. **`sw.js` 를 캐시하지 않는 게 핵심**이다 —
캐시되면 새 버전을 영영 못 찾는다. 해시가 붙은 `assets/` 는 영구 캐시해도 안전하다.

### 폰에서 홈 화면에 추가

- **아이폰** — 반드시 **사파리**로 접속. 공유 `↑` → 홈 화면에 추가
- **안드로이드** — 크롬 메뉴 → 앱 설치

### 배포 후 첫 실행에 할 일

1. **전체 → 데이터 비우기 → 빈 상태로 시작하기** (데모 데이터를 치운다)
2. **전체 → 계좌**에서 내 계좌와 초기 잔액을 넣는다
3. **전체 → 시세 가져오기**에서 KRX 인증키를 넣는다 (기기마다 따로 넣어야 한다)

사파리에서 쓰던 기록이 있다면 홈 화면 앱으로 자동으로 넘어가지 않는다.
**백업 → 홈 화면 추가 → 복원** 순서로 옮긴다.

## 점검에서 고친 것 (2026-09-23)

외부 점검 보고서를 받아 확인한 뒤 고쳤다. 지적은 전부 사실이었다.

### 금액을 조용히 다른 값으로 바꾸던 문제

입력할 때마다 `replace(/[^0-9]/g, '')` 로 숫자가 아닌 글자를 지우고 있었다.
그래서 사용자가 모르는 사이에 값이 바뀌었다.

```
'1.5'   → '15'    →     15원   (10배)
'100.5' → '1005'  →  1,005원   (10배)
'-100'  → '100'   →    100원   (부호가 사라짐)
```

`core/amountInput.ts` 에서 **정리와 검증을 갈라 놓았다.**
쉼표·공백은 조용히 없애고(`'1,500'` 은 1500 이 맞다),
소수점·부호·글자는 지우지 말고 **오류로 알린다.**
금액을 받는 네 화면(거래 수정·예산·반복 거래·초기 잔액)이 같은 `AmountField` 를 쓴다.

### 거래의 계좌·카테고리를 고칠 수 없던 문제

수정 화면이 날짜·금액·메모만 바꿀 수 있었다. 계좌를 잘못 골랐으면 지우고 다시 넣어야 했다.
계좌·카테고리·유형(지출↔수입)을 모두 고칠 수 있게 했다.
이체는 구조가 달라(받는 계좌가 필수) 유형 전환에서 제외했다.

### 미수 정산을 끝낼 방법이 없던 문제

`markSettlementReceived()` 를 만들어 놓고 **화면에 연결하지 않았다.**
정산 수정 화면에 입금 기록을 넣고, **부분 입금**을 지원하도록 모델을 넓혔다
(`Settlement.receivedAmount`). 여러 번 나눠 받아도 누적된다.

`receivedAmount` 가 없고 `receivedDate` 만 있는 옛 기록은 전액 받은 것으로 읽는다 —
그래서 마이그레이션이 필요 없다.

홈의 '아직 못 받은 정산금' 배너는 `?pending=1` 로 **미수 정산만 걸러진 목록**으로 간다.

### 그 밖

- `38,000` 이 `3만` 으로 보이던 축약 표기를 `3.8만` 으로 고쳤다 (1만~10만 구간만 소수 유지)
- 달력이 지출만 세서 월급날이 빈 칸으로 보였다 → 수입도 함께 센다
- 검색 중에도 상단 합계가 월 전체였다 → 검색 중에는 **그 결과의 합계**를 보여준다
- 내역의 '잔액' 은 계좌 잔액과 헷갈린다 → **'수입−지출'** 로 바꿨다
- 순자산에서 미수금을 뺀 기준을 카드에 적었다 (못 받을 수도 있는 돈이라 보수적으로 제외)

### 반영하지 않은 제안

**CSV 내보내기 복구** — 5단계에서 만들었다가 사용자가 직접 빼라고 해서 지운 기능이다.
점검자가 그 맥락을 몰랐던 것으로 보인다.

**미수금을 순자산에 포함** — 못 받을 수도 있는 돈이라 빼는 쪽을 유지했다.
대신 기준을 화면에 적어 오해를 없앴다.

## 달력 읽는 법

하루의 **수입 − 지출** 하나만 보여주고, 어느 쪽이 큰지는 색으로 나타낸다.

- **빨강** — 지출이 더 많은 날
- **파랑** — 수입이 더 많은 날
- 진하기는 금액 크기 (그 달의 사분위로 나눈다)

금액은 **줄이지 않고 숫자 그대로** 적는다 (`38,000`, `500,000`).
`3.8만` 같은 축약은 한눈에 크기를 가늠하기 어렵고, 칸에 실제로 다 들어간다.

수입과 지출을 두 줄로 나눠 적으면 칸이 좁아 읽기 어려워서, **차이 하나**만 보여준다.
그날의 수입·지출을 따로 보려면 날짜를 누르면 된다.

색만으로 의미를 전달하지 않도록 달력 위에 뜻을 글자로 적어 두었다.
